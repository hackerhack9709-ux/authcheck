Exhibit B · What we look at

Ten independent signals.

No single technique can answer "is this real?". Each is weak alone and useful together.

SIGNAL / 01

Provenance — C2PA

Signed Content Credentials record who made the file, on what device, and every edit since. A broken hash means the file changed after signing.

Strongest · cryptographic
SIGNAL / 02

Metadata — EXIF

Camera make and model, capture date, GPS, and the software that last saved it — including AI generators that leave their name behind.

Strong when present
SIGNAL / 03

Pixel forensics — ELA

Error Level Analysis re-saves the image and measures what changed. Locally edited or pasted regions light up brighter than their surroundings.

Visual · shows its work
SIGNAL / 04

Generation tells

Generator-sized canvases, perfect squares, absent EXIF and an unusually smooth noise profile are weak hints of synthetic origin.

Weak alone · needs context
SIGNAL / 05

Claim language

Forward-bait phrasing, unnamed "experts", heavy capitals and share requests are the fingerprint of viral misinformation — whatever the topic.

Text only
SIGNAL / 06

Claim references

Keyless by default: pulls Wikipedia and DuckDuckGo background for the claim's key terms. Add a free Google Fact Check Tools key to also match published fact-checks.

Keyless · optional key
SIGNAL / 07

Audio forensics

Container metadata, TTS/voice-clone tool signatures, clipping, RMS level and silent-segment stitching — all without a model.

Voice · signal based
SIGNAL / 08

Multilingual claims

Red-flag lexicons for English, Hindi, Urdu, Bengali, Marathi, Tamil and Spanish — auto-detected from the script used.

7 languages · script detection
SIGNAL / 09

Video forensics

Container facts, stream metadata and evenly sampled keyframes run through the full image engine, then fused into one verdict.

Clip · keyframe sampling
SIGNAL / 10

API first

Every layer is a plain JSON endpoint you can call from your own app, bot or newsroom tool. Works with no key at all; a key just raises the hourly ceiling.

Free · metered endpoints
Exhibit C · Method

How the verdict is assembled.

Every signal is weighted, then fused into one score — with the arithmetic shown.

1

Read

Provenance manifest and EXIF are pulled from the raw bytes; video containers are probed with ffmpeg.

2

Inspect

ELA and noise profiling look for edits and synthetic smoothness.

3

Match

AI-tool signatures and generator dimensions are matched against knowns.

4

Weigh

Each finding carries an explicit weight, positive or negative.

5

Explain

One score, one band, and the full reason list — always.

Exhibit E · What this cannot do

Honest limits.

A tool that never admits uncertainty is a tool you should not trust.

Absence is not guilt

Most cameras and apps still do not sign content. Missing credentials are normal and treated as neutral — never as proof of faking.

Watermarks get stripped

Invisible watermarks can be removed by widely available tools, so a missing watermark means very little. Provenance is weighted higher because it is cryptographic.

Classifiers can be fooled

Detection models degrade against new generators. That is why the score blends signals rather than trusting one model's opinion.

Video is weaker than stills

Video checks read container metadata and sampled keyframes. There is no lip-sync or temporal-consistency model, so a clean video result is weaker evidence than a clean image result.

Truth is not a pixel property

A genuine photo can illustrate a false claim, and a real quote can be framed dishonestly. The score is about the artefact — you still check the source.

Exhibit F · Interface

Use it from code.

Same engine, plain JSON. Anonymous use is rate-limited by IP; add a key for more headroom.

$ curl -X POST <base>/api/check-text -F "text=claim to check"
{ "score": 38, "verdict": "likely-misleading", "flags": [ … ], "factcheck": { … } }
$ curl -X POST <base>/api/analyze-image -F "file=@photo.jpg"
{ "verdict": { "score": 62, "band": "unclear - check sources", "reasons": [ … ] },
  "c2pa": { … }, "exif": { … }, "ela": { … }, "heuristics": [ … ] }
$ curl -H "X-API-Key: ac_…" <base>/api/usage
{ "tier": "pro", "limit_per_hour": 2000, "remaining": 1998 }
POST/api/analyze-image Multipart image upload → full dossier: provenance, EXIF, signatures, ELA image, heuristics, fused verdict.
POST/api/check-text Form field text → red-flag findings, score and fact-check matches when a key is configured.
POST/api/analyze-audio Audio upload → container metadata, TTS signatures, clipping/silence analysis, fused verdict.
POST/api/analyze-video Video upload → container facts, sampled keyframes run through the image engine, fused verdict. Needs ffmpeg (bundled via imageio-ffmpeg).
GET/api/tiers The tiers and their hourly quotas, so a client can self-serve.
GET/api/usage Live quota for the caller. Send X-API-Key to see the keyed tier.
GET/api/health Liveness, enabled layers, supported languages, and fact-check status.
Requests over the limit return 429 with a Retry-After header. Every metered response carries X-RateLimit-Tier, X-RateLimit-Limit and X-RateLimit-Remaining.
